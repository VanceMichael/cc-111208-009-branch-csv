# 预约导出接收规则

## 来源身份

- 来源身份是**完整文件的 SHA-256**，不是路径或文件名。接收时按块流式复制到内容寻址目录（`blobs/<sha256>`），随后一切读取都来自该副本。替换后的文件是另一份来源，旧决定不会跟随。
- 原始字节从不修改。复核只写独立的 `decisions` 覆盖表。

## 编码与方言

- 可显式指定编码与 CSV 方言，或给出候选集合。默认候选编码为 `utf-8-sig`、`gb18030`；默认候选分隔符为 `,`、`;`、TAB、`|`。
- 判定只读取文件开头的有界样本（4 KiB）。候选合法需同时满足：样本严格解码成功（不得替换、不得忽略解码错误），且首条逻辑记录在候选分隔符下至少切出两个字段。
- 只有一个合法候选时才自动采用。多个合法候选一律报 `encoding_ambiguous` / `delimiter_ambiguous`，并列出候选，等待显式选择；**不会默认逗号**。
- 纯 ASCII 数据在 UTF-8 与 GB18030 下都合法，因此是歧义而非默认 UTF-8。含非 ASCII 且 UTF-8 严格解码失败时，GB18030 成为唯一候选并被采用。
- 引号为双引号，字段内双引号以两个双引号转义；支持跨行文本与 CRLF。BOM 只在文件开头处理；记录中间出现 BOM 字节会被隔离为 `mid_file_bom`。

## 逐逻辑记录

- 扫描按块进行，只持有“一个块 + 一条逻辑记录”，不会把整个文件读入内存。
- 每条逻辑记录保存半开字节区间 `[start, end)`（含终止符）与 1 基物理行范围（含首尾；引号内换行也计行）。
- 记录末尾没有换行符但引号平衡时，仍是完整记录；引号未闭合则隔离为 `unbalanced_quote`，且不继续解析其后的字节。

## 映射 v1

字段固定为 `bookingId`、`date`、`region`、`note`，各出现一次；日期为 ISO `YYYY-MM-DD`；`bookingId` 非空。

映射版本 `mapping_version` 由编码、分隔符与确认表头字段（顺序与拼写）决定。换编码、换分隔符或换表头都会产生新版本。

中段重复表头只有在逐字段与确认表头完全一致时才跳过。仅是“像表头”的记录（首字段相同且至少两个已知字段）进入 `header_mismatch` 隔离。

## 隔离

以下情况保留证据，不截列、不补空、不覆盖：

| 原因 | 含义 |
| --- | --- |
| `width_mismatch` | 字段数与表头不同 |
| `bad_date` | 日期不是合法 ISO 日期 |
| `missing_booking_id` | 预约号为空 |
| `conflict` | 同一预约号已存在不同规范内容 |
| `header_mismatch` | 中段表头与确认表头不一致 |
| `mid_file_bom` | BOM 出现在文件开头之外 |
| `unbalanced_quote` | 引号未闭合 |
| `decode_error` / `csv_error` | 该记录无法严格解码或解析 |

同一预约号、相同规范内容重复接收时结果是幂等重复（`duplicate`），不会覆盖；内容不同则隔离为 `conflict`，而不是最后一条生效。

## 复核

- 复核决定是不可变字段覆盖，键为（来源摘要、记录字节区间、映射版本）。三者任一变化，旧决定都不适用，记录保持待复核。
- 复核在后续接收时以字段覆盖方式生效；同一文件、同一映射重跑会复用已核准决定。
- 复核只接受已隔离记录、已知字段；同一记录同一字段不可重复提交。
- 业务行、隔离证据和恢复检查点在同一 SQLite 事务中提交，检查点只记录完整逻辑记录的边界。

## 示例

`fixtures/demo-bookings.csv`（由版本化 base64 还原）包含：跨行 CRLF 备注、一条坏日期待复核记录、一条中段重复表头、一条同预约号不同内容的冲突记录。`python -m scripts.demo` 演示接收、原文切片、复核、重跑复用与中断续跑。
